# RADZONE — Gameplay Art Wave 2026-11-10

## What was actually created

A new image-generated composite was transformed into **10 independent RGBA PNG art candidates**, each at 128×128 and 256×256, with alpha matte and SHA-256 tracking. This is **20 new raster PNG files** (5 weapons, 3 armor components, 2 world props), plus a source sheet, a visual review sheet, an engine preview scene and two instantiable world prop scenes.

Source and review files are stored in `art/production/wave_2026_11_10/`; see `manifest.json` for exact filenames, checksums and alpha bboxes. These are cropped and segmented from a composite image, so details were originally smaller than 256 pixels and cannot be claimed to have newly generated 256-pixel native detail.

## How to test in Godot

- Run `scenes/art_preview/gfx_wave_20261110.tscn` separately. This scene is QA-only: it deliberately does not alter the main menu or gameplay state.
- Drag either `scenes/world/props/gfx_wave_20261110/workbench.tscn` or `portable_generator.tscn` into a sandbox map and verify the bottom-center pivot, occlusion, collision (not supplied), alpha edges, actual scale, and texture filtering.
- For weapon and armor art, do **not** infer that a side-view icon is an eight-direction rigged world sprite. Determine existing canonical item ID and approved visual mapping before any integration; preserve SPECIAL, DT/DR, damage, equip events and save data.
- Compare visual quality to the already-approved 10 RADZONE UI concepts; reject any clipped, inconsistent or low-resolution artwork before integrating into a production scene.
- Use `python tools/validate_art.py --require-alpha <path-to-png>` and run Godot 4.7.2 import and Android smoke checks in OpenCode on Windows.
