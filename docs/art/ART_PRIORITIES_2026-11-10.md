**Owner:** ChatGPT — art direction, production briefs, asset QA and GitHub publishing. **Implementation:** OpenCode — integration/rigging/testing in Godot/Android. **Status:** ACTIVE PLAN / draft branch, not an in-game implementation.

- **Approved visual target:** 10 images under `github-assets/approved/v2/` and `docs/art/APPROVED_VISUAL_CATALOG.md`. These are approved *concepts*, not gameplay screenshots.

- Godot already has `CharacterVisual` paper-doll layers, equipment synchronization and eight facing names `S, SW, W, NW, N, NE, E, SE`; do not rewrite functional systems.
- Pistol Rev2 Blender production attempt was rejected as quality target. Keep it only as technical placeholder/review history.
- The 2026-11-10 ChatGPT attempt to create an isolated survivor-with-pistol concept **failed technically; no asset was produced or committed**. Await a subsequent image-generation request or use verified OpenCode provider. Never report a missing file as generated.

## Art priorities and acceptance gates

| Priority | Deliverable | Reuse and produce | Complete only when |
| --- | --- | --- | --- |
| **P0A** | One player visual vertical slice | Audit existing survivor views and exact canonical pistol item ID; create one validated, properly anchored **pistol-in-hand** overlay/pose reference, then aligned production frames | User accepts visual quality; OpenCode proves pistol equip/unequip in live Godot capture without breaking gameplay |
| **P0B** | Full 8-direction weapon visual contract | Unarmed → pistol → rifle → knife, idle/walk/attack; hand sockets, occlusion, muzzle origin, directional naming; replace neither item stats nor animation names | 8 directions × required states actually shown, tested in inventory and combat, save/load and Android verified |
| **P1** | Wearable gear | Leather/metal armor, helmet/mask, backpack; body/head/hands/feet/pack layers, consistent silhouette | Exact existing IDs map to unique supported looks and every change is visible in-world |
| **P2** | Inventory items and icons | Refine existing 15 draft item crops first. Export approved transparent icons at **actual discovered** target sizes, no hardcoded false labels | All icon alpha/scale/visual checks + inventory/barter/loot runtime previews pass |
| **P3** | NPC visual cast | Existing raider 8 concept views + new civilian/merchant/guard, varied age/body/hair/clothing, separate equipment overlays | Distinct silhouettes and working equipment shown for NPC in Godot |
| **P4** | World art | Existing 14 draft world props, modular isometric tiles, surfaces, debris, buildings, collisions, draw order | Grounded scale and playable level screenshots; alpha and occlusion QA |
| **P5** | Full UI polish | Existing 13 draft UI components; approved main menu/dialogue/SPECIAL/combat/map/barter/loot concepts | Fully functional touch UI; actual HP/AP/stats/dialogue generated by Godot, responsive landscape Android |

**Why P0 before interface polish:** The main product differentiator demands that equipped weapons and armor actually change the player and NPC appearance. Existing v3.1 images do not include full gameplay animations and cannot be marked production-ready merely because they have transparent backgrounds.

## Required artifact manifest

For every file: item ID, visual ID, original source path, generator/editor, reference image hashes, SHA-256, dimensions, alpha bbox, direction, animation, hand grip pivot, ground pivot, draw order, source license, review status, Godot evidence and reviewer.

Status labels: `approved_concept`, `draft_reference`, `candidate_asset`, `in_game_verified`, `deprecated_experiment`. No premature `in_game_verified` designation.

## Safety and working style

- Preserve 73 previously documented tests, the working debug/release builds, original RPG balance and save compatibility; numbers remain live game data.
- No generated text/numeric RPG stats baked into graphics.
- No bulk generation before one object passes visual QA and Android runtime QA.
- No changes to approved RADZONE gallery unless user explicitly approves.
- No fake sources, forged screenshots, test claims or speculative GitHub paths.
- Keep REA MCP disabled.
- GitHub as source of truth; no user downloads required for documentation.
