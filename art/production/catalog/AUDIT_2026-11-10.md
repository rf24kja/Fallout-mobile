## Findings / non-claims

- No pixel-level similarity scan of *all* GitHub branches was executed here: reference image binaries from other branches are not all present in one local worktree.
- Different SHA-256 values do not prove that two files depict different objects.
- The same object may legitimately have 64px/128px/256px sizes, inventory versus world renders, and directional animation views. Those belong to one canonical item, not multiple item counts.
- No existing game asset was removed, renamed, overwritten or automatically rejected.
- New binary art is NOT published in this audit PR. Newly generated weapon/armor/loot boards shown previously were not counted as 18 unique objects.

## Required gate before the next batch

1. Search `asset_registry.json` by name, aliases and subject/function before generating.
2. Use `tools/art/asset_uniqueness_guard.py --candidate-id <new-id> --candidate-image <file>` to detect ID, SHA-256 and perceptual similarities; pass `--reference-root REF=DIR` for every staging worktree.
3. An unavailable reference image is not a PASS. Mark `INCOMPLETE_VISUAL_AUDIT` and request comparison in OpenCode.
4. Publish only a genuine isolated PNG candidate after human visual review. Record canonical ID, original generation source, model, license, alpha bbox and Godot mapping.
5. Approval is a separate gate from valid PNG, GitHub upload and Godot import.

## Warnings about image-generation errors

- A previous invalid image-generation invocation supplied `animation.frame_count=1` although frame_count requires at least 2. **For static sprites omit the animation settings entirely.**
- A later refusal was from the image-generation safety check. The system did not provide a definitive trigger; it is not proof of an illegal project or a GitHub permission issue.
- Do not claim a generated or uploaded artifact unless its actual bytes and GitHub file path are verified.
